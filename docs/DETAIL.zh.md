# 归档会话清理

在 DeepSeek Harness 里，"归档"只是把会话从侧栏隐藏，日志仍原样占用
`~/.dsh/sessions` 下的空间。宿主没有提供"删除会话"的入口，这个插件补上这一步，
并且只允许删除已归档的会话。

## 入口

设置 → **归档会话清理**。页面按工作区分组列出当前归档集合中的全部会话，显示标题、
最后更新时间、磁盘占用，以及它带有的子会话数量。

## 如何删除

1. 勾选要删除的会话（也可以点「全选可清理项」）。
2. 点「永久删除所选…」并确认。
3. 插件会先把选中的会话完整复制到
   `~/.dsh/cleanup-backups/cleanup-backup-<时间戳>/`，并写入 `manifest.json`
   （记录每个原始路径、文件清单、大小，以及 `workspace.json` 的哈希）。
4. 备份成功后才真正删除 `sessions/<项目>/<id>/` 与
   `storages/session_projcache/<id>.json`，随后从各工作区的会话账本和归档集合里
   移除该 id。

如果被选中的归档会话还带有子会话（`parentSession` 链指向它），子会话会一并删除；
确认框会先告诉你数量。

## 拒绝删除的情况

- 不在归档集合中的会话：跳过（`not-archived`）。
- 宿主当前已加载或正在运行的会话：跳过（`in-use`）。
- 目录不在会话根目录之下的：跳过（`outside-root`）。
- 备份失败时：一个字节都不删，请求以 `backup-failed` 失败返回。

结果区会分别报告已删除的会话、释放的空间、备份目录，以及被跳过或失败的 id。

## 打开备份文件夹

工具栏的「打开备份文件夹」在系统文件管理器里打开 `~/.dsh/cleanup-backups`；
「最近的备份」列表里每一条都有「在文件夹中打开」。宿主只接受备份根目录之内的
名称，任何 `..` 或绝对路径都会被拒绝（`invalid-backup`）。

## 从备份恢复

0. 直接点工具栏的「打开备份文件夹」；每个备份右侧的「在文件夹中打开」会定位到
   那一次备份的目录。`~/.dsh/cleanup-backups` 尚不存在时，入口会先创建它。
1. 把 `cleanup-backup-<时间戳>/sessions/<项目>/<id>/` 复制回
   `~/.dsh/sessions/<项目>/<id>/`。
2. 把 `cleanup-backup-<时间戳>/session_projcache/<id>.json` 复制回
   `~/.dsh/storages/session_projcache/`。
3. 用备份目录里的 `workspace.json` 覆盖当前文件（它与备份时刻的归档集合一致），
   然后重启 DeepSeek Harness。

## 说明

- 搜索索引是从会话持久化数据派生的，删除后会在下一次列表或查询时自动收敛，
  不需要额外清理。
- 标题和工作区名称来自客户端已有的会话/工作区快照，插件不解析会话日志。
- 路由同时注册在 Web 服务器的 `/archived-cleanup/*` 和桌面端 Connection 通道的
  `/api/archived-cleanup/*`，两者都经过宿主的浏览器访问围栏。
